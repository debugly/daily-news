2026-11-20｜统计周期：11月13–19日

## 1. OpenCode（首次）
[GitHub](https://github.com/anomalyco/opencode) · [v2.3.1](https://github.com/anomalyco/opencode/releases/tag/v2.3.1)
11月18日发布。超时但仍运行的 Shell 命令转入后台，提前后台生成上下文压缩摘要，修复僵尸进程、子 Agent 权限、模型切换推理字段及 ACP 后续消息。区别于简单模型 CLI，关注长任务生命周期和会话恢复。适合大型 C/C++ 编译测试；后台任务仍可能消耗资源、修改文件，压缩可能浪费 Token。
[PR 63699](https://github.com/anomalyco/opencode/pull/63699) · [PR 64290](https://github.com/anomalyco/opencode/pull/64290)

## 2. Dify（首次）
[GitHub](https://github.com/langgenius/dify) · [1.20.0](https://github.com/langgenius/dify/releases/tag/1.20.0)
11月18日发布。知识库索引前恶意软件扫描、OpenTelemetry Collector Trace 导出、Langfuse 集成适配、Chatflow 实时工具活动和 PAT。区别于简单向量检索示例，关注生产安全、权限与调用链。已有工作流及插件生态；管理 PAT 作用域、轮换及泄露，扫描不能代替文档 Prompt Injection 防护。适合多人知识库。

## 3. Cognee（首次）
[GitHub](https://github.com/topoteretes/cognee) · [v1.6.10](https://github.com/topoteretes/cognee/releases/tag/v1.6.10)
11月18日发布。收紧每数据集 PostgreSQL 连接池默认参数，明确等待超时，记录嵌套 LLM 调用及调用者元数据，强化 Chunk 有效性检查。区别于一次性向量索引，强调持续运行的数据系统。正式版本；连接池变化可能更早触发 pool exhausted，升级前测试并发写入与耗尽。适合多租户 GraphRAG。
[PR 6744](https://github.com/topoteretes/cognee/pull/6744)

## 4. OpenHands（首次）
[GitHub](https://github.com/OpenHands/OpenHands) · [v1.42.0](https://github.com/OpenHands/OpenHands/releases/tag/v1.42.0)
11月18日发布。仓库明确选择 Git 提供商、恢复 Webhook 来源校验、改善验证环境 HTTP Origin（PR #19762、#19600、#19756）。区别于代码补全，关注完整软件工程执行环境。适合仓库自动化；审计凭据、Webhook、执行权限，原报告指出 macOS 桌面应用签名公证尚未完成。

## 5. AG-UI（首次）
[GitHub](https://github.com/ag-ui-protocol/ag-ui) · [文档](https://docs.ag-ui.com) · [规范](https://github.com/ag-ui-protocol/ag-ui/tree/main/spec) · [SDK](https://github.com/ag-ui-protocol/ag-ui/tree/main/sdks)
类型化双向事件流：RunAgentInput、运行状态、文本、工具调用、状态更新。MCP 连接工具，A2A 连接 Agent，AG-UI 连接用户界面。11月17日社区约19300 Stars，原报告查看约20600 Stars、5500累计提交及数百 Issue/PR，非严格七日增量。原报告称已有1.0规范及 TypeScript/Python/.NET SDK，Swift/C++ 社区 SDK。适合跨框架 Web、桌面、移动客户端；检查 SDK 一致性、重放、取消、恢复及授权。

## 6. claude-mem（持续跟踪）
[GitHub](https://github.com/thedotmack/claude-mem) · [v16.0.0](https://github.com/thedotmack/claude-mem/releases/tag/v16.0.0)
11月18日发布。My Work 重构，人工请求置顶，压缩长列表，改善手机、键盘和屏幕阅读器交互；移除旧 Observation TV 远程入口，网络访问使用本地 API Token。由历史记忆扩展到长期任务人机协作。快速迭代，删除 /tv、tv.html 和旧 Token 设置需迁移。关注绑定地址、认证、审批队列及会话关联。

## 7. llama.cpp（持续跟踪）
[GitHub](https://github.com/ggml-org/llama.cpp) · [b12527](https://github.com/ggml-org/llama.cpp/releases/tag/b12527)
11月18日预发布构建。Limite 模型 MUDD 配置中 n_layer * n_mudd_taps 可能超过长度512的 mudd_tap_idx；加载超参数时拒绝超范围配置，覆盖张量加载与计算图构建路径。区别于性能优化，这是不可信模型解析的边界验证。跨平台工程较成熟，但滚动预发布不等于稳定版本，也不代表所有解析路径安全。适合 C/C++ 原生开发者研究。
[PR 32562](https://github.com/ggml-org/llama.cpp/pull/32562)

## 趋势与建议
Agent Runtime 重视长任务、中断恢复；RAG 转向生产安全、数据一致性和可观测性；模型文件与 Webhook 均是不可信输入。优先研究 OpenCode 后台命令及上下文压缩、llama.cpp 模型边界检查、AG-UI 与 SwiftUI/Web 的事件解耦。版本日期以原报告 Release/PR 为依据，未虚构七日 Star 增量；成熟度并非独立性能或安全审计。
